## Driver Architecture

### Connection lifecycle

```
connect:     Build DPB (user, password, charset) → isc_attach_database()
disconnect:  Rollback active transaction → isc_detach_database()
reconnect:   disconnect() + connect() loop
```

### Transaction interception

Firebird's ISC API doesn't accept BEGIN/COMMIT/ROLLBACK as SQL strings. The
driver intercepts these in `firebird_drv_query()`:

- `"BEGIN"` → `isc_start_transaction()`
- `"COMMIT"` → `isc_commit_transaction()`
- `"ROLLBACK"` → `isc_rollback_transaction()`

For DDL and standalone queries with no active transaction, the driver starts
an implicit auto-transaction and commits after execution.

### Prepared statements

Full XSQLDA-based prepared statement support:

1. `prepare`: `isc_dsql_allocate_statement()` → `isc_dsql_prepare()` → `isc_dsql_describe_bind()`
2. `bind_param`: Map sysbench types to XSQLVAR (`SQL_LONG`, `SQL_VARYING`, etc.)
3. `execute`: `isc_dsql_execute()` → fetch results → `isc_dsql_free_statement(DSQL_close)`
4. `close`: `isc_dsql_free_statement(DSQL_drop)`

### Result set storage

Results are fetched entirely into memory via `fb_fetch_all_rows()`, which
stores each column value as a string in `fb_result_t`. This matches the
PostgreSQL driver's approach (PGresult stores all rows client-side).
`fetch_row()` returns values by row index, like `PQgetvalue()`.

### Error handling

- Lock conflicts (SQLCODE -913) and unique violations (-803) return
  `DB_ERROR_IGNORABLE` — sysbench retries the transaction
- `sql_state` and `sql_errmsg` are heap-allocated via `strdup()` to survive
  past the ISC_STATUS array lifetime (required by Lua FFI layer)
- Error status is preserved with `memcpy(saved_status, status, ...)` before
  cleanup calls that would overwrite the status vector

### SQL dialect handling

All handled inside the driver, never in Lua scripts:

| Feature | How handled |
|---|---|
| No multi-row INSERT | `drv_caps.multi_rows_insert = 0` triggers per-row flush |
| No auto-commit | `drv_caps.needs_commit = 1`, driver manages transactions |
| `DROP TABLE IF EXISTS` | Strips `IF EXISTS`, executes, ignores -607 |
| `CREATE TABLE IF NOT EXISTS` | Strips `IF NOT EXISTS`, executes, ignores -607 |
| `GENERATED BY DEFAULT AS IDENTITY` | DDL branch in `oltp_common.lua` |
| Auto-inc insert (omit id column) | Branch in `oltp_insert.lua` |

### Core sysbench fix

`db_driver.c`'s `db_bulk_do_insert()` originally used `con->error != DB_ERROR_NONE`
to detect failures, which treated `DB_ERROR_IGNORABLE` as fatal. Changed to
`con->error == DB_ERROR_FATAL` so ignorable errors (lock conflicts during bulk
insert) don't abort the operation.

Also added per-row flush for drivers without multi-row INSERT support: after
each `db_bulk_insert_next()`, if `bulk_single_row` flag is set (from
`db_bulk_insert_init()`), `db_bulk_do_insert()` is called immediately.

## Build system integration

The Firebird driver follows the exact same pattern as MySQL and PostgreSQL:

1. `m4/ac_check_firebird.m4` — checks `--with-firebird=PATH`, falls back to
   `fb_config`, supports `--with-firebird-includes` and `--with-firebird-libs`
2. `configure.ac` — `AC_ARG_WITH([firebird])`, `AC_CHECK_FIREBIRD`,
   `AM_CONDITIONAL(USE_FIREBIRD)`
3. `src/drivers/firebird/Makefile.am` — builds `libsbfirebird.a`
4. `src/Makefile.am` — links `libsbfirebird.a` + `-lfbclient`
5. `src/db_driver.h` / `src/db_driver.c` — `#ifdef USE_FIREBIRD` registration

## Test infrastructure

11 Cram test files following the MySQL/PostgreSQL test patterns:

- `firebird_common.sh` extracts connection parameters from `SBTEST_FIREBIRD_ARGS`
  environment variable and finds `isql` via PATH (no hardcoded paths)
- Tests use `\s* (re)` regex patterns for blank lines (sysbench outputs
  trailing whitespace that Cram is strict about)
- Each test is self-contained: creates tables, runs operations, drops tables
- The `script_oltp_general_firebird.t` test verifies table structure via `isql`

## CI

GitHub Actions workflow includes a `build_firebird` job that:

1. Installs build dependencies on Ubuntu 24.04
2. Builds Firebird 5.0.4 from source
3. Installs to `/opt/firebird`
4. Builds sysbench with the Firebird driver
5. Starts Firebird server
6. Runs full prepare → run → cleanup cycle
